## Source and execution scope

The final suite used normal hosted terminals. Earlier terminal connection failures, cached assets and command-launcher attempts are retained as history; launcher-reported output alone is not used as proof. Retakes replaced affected final records. Source fingerprints or explicit byte comparisons with the immutable tested commit bind every indexed checker to the current source.

Most runs independently hashed every delivered asset. CKA service-repair and Kustomize used immutable tested-commit byte equivalence; their original runs did not capture an independent full-file hash. For CKS image-admission, offline audit and host-security, the setup, solution and indexed checkers were hashed, while some executed auxiliary helpers were not separately hashed. These limits are retained in each record; the report does not claim independent hashing of every auxiliary file.

Native bootstrap was replayed from a full reset with the published final helper pinned after the initial session had received an older cached helper. HA was tested through real join, member outage, load-balanced writes and recovery; a fresh automatic-delivery follow-up separately confirmed the final published assets. The two-node upgrade received the final assets automatically and passed the control-plane CHECK before the worker upgrade.

## Runtime issues corrected and retested

- Native package selection no longer exits early under pipefail; package operations and reboot prompts work in the provider terminal.
- The hosted two-node underlay uses Cilium VXLAN on UDP port 4789 with MTU 1400. Packet captures and successful DNS from both nodes established these settings.
- NetworkPolicy checks exercise real allowed and denied traffic with Cilium identities, including the same-namespace peer and metadata isolation.
- HA setup tolerates the brief API interruption after resetting a member. Join handles the observed nested-host kernel-config and conditional CPU preflight constraints; recovery waits for the container runtime after a cold restart.
- Worker maintenance preserves its intended resident workload across a drain; the checker rejects a terminating replacement.
- Missing starting-state answer files and HTTPRoutes now produce readable checker failures instead of Python tracebacks.
- Autoscaling uses a 50m CPU request on the observed one-CPU hosted VM so the requested replicas fit. It still requires real CPU metrics, scaling above one replica and a fully ready Deployment. The hosted task explains this adaptation from the book example.

Ordinary hosted clusters were observed on Kubernetes 1.36.1. Native bootstrap installs its specified version and the upgrade lab performs a real 1.34.12 to 1.35.9 upgrade. HA uses three control-plane containers and a load balancer on one provider host, proving member/process failure and quorum rather than independent physical-host resilience.

The [local validation](VALIDATION.md) remains a separate dated record: 28 labs and 72 local checks. The [7 October hosted report](HOSTED-VALIDATION-2026-10-07.md) preserves the earlier 12-lab suite. Future source or backend changes require affected checks to be repeated.
